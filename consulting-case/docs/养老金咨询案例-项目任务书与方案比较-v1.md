# 个人养老金开户后服务优化

> 版本说明：保留10月9日任务书快照；后续公开统计与本地原型再执行结果见[10月10日复核报告](养老金咨询案例-原始材料与原型复核-v1.md)。
## 项目任务书与方案比较 · v1

编制：吕滢滢｜日期：2026年10月9日

项目性质：基于个人参赛方案整理的独立咨询案例。研究情境中的银行为假设客户；本案例不是银行委托项目，也不代表银行审批意见。

## 一、项目任务书

### 1. 业务问题

对已开户、尚未首缴的客户，银行应优先改善自助说明入口，还是增加获准主动联系？在什么客户保护、效果证据与成本条件下，值得继续试点或扩大投入？

本案例帮助银行比较不同服务方案的投入价值，通过用户研究、流程诊断、风险控制和试点设计，提出分阶段验证方案。现有证据支持方案设计，尚不足以证明真实业务效果。

### 2. 决策使用者

假设由银行个人养老金业务负责人牵头，渠道与客户服务、技术与数据、风险与合规、消费者权益保护及经营测算相关人员共同评审。该安排为案例中的建议分工，非工行实际组织与审批流程。

### 3. 研究范围

| 纳入范围 | 本次不作结论的事项 |
| --- | --- |
| 开户后的规则理解、服务选择、操作与结果确认 | 真实银行客群规模与未首缴率 |
| 现有服务、说明入口、获准主动联系、完整适配服务的比较 | 未取得真实试验结果的服务增量与ROI |
| 资格、许可、暂缓、最少信息、人工接管和事件记录等控制 | 银行正式合规审批与生产环境有效性 |
| 分别配对的效果、成本与贡献测算 | 具体金融产品的投资推荐 |
| 试点指标、评价口径、停止与扩展条件 | 将拟议AI、Uplift或动态策略写成已上线能力 |

### 4. 成功标准

咨询案例完成的标准：

1. 阅读者能在两分钟内找到核心问题、初步建议和证据限制。
2. 四种方案的比较有明确依据；未知项标为待核，不用虚构评分填补。
3. 商业测算可复算，假设、来源、单位和不确定性明确；缴存额不作为银行收入。
4. 每项关键风险有控制、测试方式和证据状态；开发自检与真实银行验证分开。
5. 试点方案区分入口增量与主动联系增量，不以点击或自然首缴替代服务效果。
6. 吕滢滢能用五分钟解释问题、方法、建议、个人分工与局限。

这些是作品交付标准，不代表真实业务已经达到效果或客户保护目标。真实试点的指标与阈值需由银行事前批准，本案例不自行编造。

### 7. 初步建议与当前决策

当前建议进入“数据与控制核验、试点准备”阶段，而非直接扩大服务投入。

- 先核验客群、许可、现有流程和成本，明确说明入口与主动联系各自解决的问题。
- 在经批准且可评价的条件下，分别检验B−A和T−B；样本不足时采取分阶段验证。
- 完整适配服务C另设评价，不把首期入口或主动联系结果归为完整适配或AI的效果。
- 客户保护是独立约束。效果证据不足、经济口径未核或保护条件不满足时，不申请扩大。

以上为待检验的建议，不宣称说明入口已经有效，也不宣称主动联系一定无效。

## 二、第一版方案比较

四种方案为决策选项，其中A/B/T也用于首期试验分组。以下成本大小和可行性均须验证，不用无依据的数字评分。

| 方案 | 可能解决的问题 | 服务形式 | 新增投入 | 主要风险或局限 | 需要验证的事项 | 当前建议 |
| --- | --- | --- | --- | --- | --- | --- |
| A：现有服务 | 保留现有自主办理与正常必要服务 | 原账户页、缴存入口及正常服务 | 作为比较基线；现有成本并非零 | 当前服务流程和障碍尚待银行核实；可能保留原有摩擦 | 现有流程、自然首缴基线、服务和成本口径 | 保留为对照，不剥夺必要服务 |
| B：增加中性说明入口 | 部分规则理解与入口查找问题 | A基础上增加说明入口，不新增主动联系 | 页面、内容审核、埋点、联调与维护；金额待核 | 未必被看到或理解；不能由访问推断首缴 | B−A的有效首缴增量、成本、理解与保护指标 | 作为候选方案优先准备验证，不宣称已有效 |
| T：入口基础上获准主动联系 | 部分客户未主动使用入口或未获取说明 | B基础上，通过许可明确、预先批准的渠道联系，允许拒绝与撤回 | 相对B新增渠道、人工、审核、运维与保护处置等成本 | 许可、打扰、频控、执行失败；增量不足以覆盖成本 | T−B增量与不确定性、成本和客户保护，执行回执与停止效果 | 条件满足后小范围验证；效果与经济证据不足时不扩大 |
| C：完整适配服务（后续候选） | 判断、流动性、步骤与人工服务分流 | 在服务路径中提供继续、暂缓、测算或人工等分支 | 规则、数据、接口、人工协作及维护；与复用项分开核算 | 信息错误、判断不适配、规则与版本冲突、系统依赖 | 另设C−B或合适对照；验证全部服务链及保护条件 | 原型可展示；实际试点另行评审，不沿用首期效果 |

### 方案比较如何使用现有调研

- 规则理解和操作障碍是方案设计线索，可支持提出B与C等候选路径，不能据此认定它们有效。
- 100份补充问卷中对主动订阅、Push或短信的接受度，只描述该样本的回答；不等于真实渠道许可，也不能估计各处理臂增量。
- 表中“可能解决的问题”是分析假设，需结合银行流程、真实反馈和试点进一步验证。

## 三、商业测算的起点：保留负结果

复用计划书第30页T−B默认模拟情景：

| 项目 | 模拟值／计算 |
| --- | --- |
| T、B各臂人数 | 各50,000名虚构入组客户 |
| 首缴率差 | 1.34%−1.30%=0.04个百分点=0.0004 |
| 折算增量人数 | 50,000×0.0004=20人 |
| 假设单位增量贡献 | 200元／人 |
| 折算增量贡献 | 20×200=4,000元 |
| 相对B新增成本 | 13,000元 |
| 情景净值 | 4,000−13,000=−9,000元 |
| 点估计盈亏平衡单位贡献 | 13,000÷20=650元／人 |

全部数值为原方案的模拟结果或可调假设，不是银行真实效果、报价或收益预测。单位贡献为简化测算假设，正式决策优先比较每名入组客户的全行净贡献。

当前解读：这一组假设不支持扩大主动联系。示意效果区间跨零，650元的点估计门槛不稳定；不能仅通过调高单位贡献假设得出扩展结论。还应同时核验效果、成本、贡献与客户保护。

## 四、下一步具体工作

下一步先制作商业测算表，不增加系统功能：

1. 建立参数字典：名称、定义、单位、默认值、来源、是否模拟、待确认方。
2. 将B−A与T−B分开配对；B缺少数值依据的项留空并列为待核，不复制T的参数冒充依据。
3. 拆分一次性和持续成本，标明分摊与复用假设。
4. 用明确标为假设的情景检查效果、贡献和人工成本变化；不把敏感性范围冒充统计置信区间。
5. 输出“可准备试点／需补证据／应暂停”的条件说明；不把本地模型变成自动银行审批。
