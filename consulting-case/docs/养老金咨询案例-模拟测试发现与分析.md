# 个人养老金服务：模拟测试发现与分析

本材料采用人为植入缺陷的虚构记录，执行表内故障规则与复算规则。不是原型漏洞发现，也不是银行实际审计结果。原矩阵中的银行控制验证仍未开展。

## F01：许可控制必须覆盖执行端

8条演示记录中，S01、S07、S08共3条在撤回时点或之后仍发送；S06缺少发送时点，不能判断符合。故障规则只在排队时读取许可，因此能拦截撤回后入队，却漏掉排队后撤回。建议在执行前重新校验，让撤回使队列任务失效，并保存取消、发送及重试回执。只有前端按钮不可点击不足以证明控制有效。

## F02：统计口径可以改变投入判断

成功流水条数给出B=4、T=6，两臂各100人，率差为+2个百分点。按自然人、事件、60天发生窗与第67天冲正核验复算，已确认B=3、T=2，另1名T客户缺事件ID待核。原分母保持不变，对待核结果的逻辑边界为−1至0个百分点。该范围不是统计置信区间；本例不足以确认正增量。需先修复重复、冲正、窗外与缺失口径，再评价服务。

## F03：净高估不代表遗漏不重要

虚构申报费用18850元，归属当前项目与窗口的支持金额15100元，净高估3750元。其中重复、已含费用与范围错配共高列4950元，审核和保护处置漏列1200元。整改必须分别删除不归属项并补列遗漏；不能仅压低总预算。支持金额为演示设定，不是实际报价。建设3000元也不是原方案3000元合计的事实分解。

## 面向管理层的建议

先完成许可执行与停止控制，再固定账务结果和缺失口径；同步逐项核费用，形成可复核投入建议。实际复核时取得队列日志、账务结果、原始费用凭据与评审依据。不要用本演示替代生产验证或真实随机试验。
